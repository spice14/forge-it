You are a highly skilled Python testing engineer. Your goal is to generate a **minimal but high-quality** set of unit tests using the `pytest` framework to achieve **just over 90%** real code coverage for the Python module provided below.

Only generate **valid, realistic test cases**. Stick to logic and functions that **actually exist in the code** — do not invent or assume behavior.

---

### ✅ Instructions

1. Output only **pure Python** code. Do NOT include:
   - Markdown fences (```python)
   - Comments or explanations
   - Duplicate or redundant tests

2. Assume the module is already imported in the test file like:
   ```python
   import <module_path> as module
```
So you must reference functions like:

module.function_name(...)

Your tests must:

1. Use def test_*(): naming

2. Import pytest if error tests are needed

3. Cover normal and meaningful edge behavior

4. Raise errors only if the code clearly handles them

Your tests must NOT:

1. Reference undefined functions like divide or sqrt

2. Include logic or inputs not inferable from the original code

3. Add unnecessary combinations just to pad coverage

✅ Style Guide
Each test should focus on a single logical assertion

One or two pytest.raises(...) calls per test file if needed

Avoid overfitting test logic (e.g., don’t simulate complex math unless clearly present)

Prefer clarity over cleverness
